## 问题陈述

上一轮设计（2026-08-13，G1–G8）已全部落地：原生工具调用、真实 MCP 客户端（HTTP/stdio）、
LLM 评估 v1、Trace/OTLP、记忆检索优化、编排升级（planning/reflection/HITL/熔断）、依赖与 CI/CD。
2026-08-22 又完成了并发收口（异步 REST、流式上限、推理闸门、按用户分文件记忆、技能注入、压测基线）。

但对照 2026 年顶级 agent（Claude Code / Codex / OpenAI AgentKit 一类的生产实践），仍存在六类结构性差距，
集中在：**长会话上下文管理、评估与回归门禁、网页/工作区工具能力、多代理编排、成本与指标、记忆纠错闭环**。
本设计不是功能清单，而是一份"差距诊断 + 分阶段升级方案"，每条带证据、方案、验收标准。

## 现状基线（2026-08-22 收口后，代码实证）

### 已具备（本设计不动，作为地基）

- ReAct 编排：原生 tool_calls + 文本工具 fallback、并行工具执行（上限 5 轮）、分支失败检测 6 信号。
- 记忆：短期 deque（100 条/TTL 24h）、5/10/8 轮 LLM 蒸馏/摘要/项目 nuggets、分层 episodic/semantic、
  向量检索（Ollama embedding + n-gram fallback、时间衰减评分）、按用户分文件落盘。
- 编排升级：planning 前置（复杂度检测 + LLM 计划）、reflection 后验、HITL 审批门（web/WS 卡片）、
  circuit breaker / 推理闸门 / 并发上限、语义缓存。
- 可观测性：TraceService（span 落盘 + OTLP/OpenInference 导出）、/api/traces、渠道指标、压测基线。
- 渠道：飞书（WS + OAuth + 卡片）、企业微信（回调，已实测送达）、Telegram（adapter 待凭证）、
  群聊静默/表情回应、渠道指标与限流。
- 安全：JWT 全链路、SecretCrypto 落盘加密、工具白名单（file 只读 / shell 命令白名单 / db 只读）、
  工具结果不可信前缀、隐私分层铁律。
- 测试：后端 505 用例、E2E 70、前端 20、perf 基线工具、CI workflow。

## 设计目标

1. 任何模型、任何会话长度下，请求不超上下文窗口且关键信息不丢（R-01）。
2. 单点故障不导致全系统不可用（R-02、R-13）。
3. 回答可验证：来源可溯（R-05）、记忆可纠（R-04）、质量可测（R-06）。
4. 能力可扩展：网页/工作区工具（R-03/R-08）、子代理（R-07）、视觉（R-14）、工具 SDK（R-15）。
5. 可运营：成本可见（R-10）、密钥可轮换（R-11）、会话可管理（R-12）、断点可恢复（R-16）。

## 详细设计

### P0 — 高价值，建议近期落地

#### R-01 上下文 token 预算与自动压缩

**问题（证据）**：`ConversationMemoryService.SHORT_TERM_MAX_SIZE=100`，`AgentOrchestrator.initialMessages()`
把 `memory.history()` 全量 `addAll` 进 messages；无 token 级裁剪。session summary 每 10 轮写入记忆，
但不参与替换历史。长会话 + 记忆召回 + 工具定义 + system prompt 可超 num_ctx（默认 16384）。

**方案**：
1. 新增 `ContextBudget` 组件：按模型 num_ctx 计算可用预算，分块分配（system / 工具定义 / 记忆召回 /
   项目上下文 / 历史 / 当前消息），每块预留比例。
2. **num_ctx 唯一来源**：`ContextBudget` 从 `ModelService` 解析模型 num_ctx（配置表 > 请求显式 > Ollama 默认），
   `PromptService.maxContextTokens` 与前端 tokenPct 均由此派生，杜绝三套数字。
3. token 估算：字符规则（CJK≈1、ASCII≈0.25 token）为主路径（O(1) 无额外 HTTP），精确计数（Ollama）仅作可选校验。
4. 历史超限时：滚动窗口保留最近 N 条，并注入最近会话摘要（从 summary 类型记忆检索，已有）；仍超则逐条丢弃最旧消息。
   **降级铁律：无可用的最近摘要时不得裁剪历史**（宁可超窗告警，不静默丢信息），告警走 trace span。
5. 工具定义超限时：按 SkillMatcher 过滤后的子集，若仍超则仅注入最常用工具描述。
6. 前端 tokenPct 改为读取后端返回的预算结构（当前硬编码 CTX_LIMIT=8192，与后端 num_ctx 可能不一致）。

**涉及模块**：`ai/memory/ConversationMemoryService`、`ai/agent/AgentOrchestrator`、
`ai/llm/ollama/OllamaLlmProvider`、`config/AgentConfig`、`frontend/src/views/ChatView.vue`。

**风险**：压缩丢细节（用摘要兜底缓解）；估算误差（保留安全边际 15%）。

**验收**：构造 200 条消息会话，请求消息体 token 数不超窗口；关键上下文（用户偏好、项目）仍召回；
测试：`ContextBudgetTest`（预算分配/边界）、`ConversationMemoryServiceCompactionTest`（窗口滚动/摘要注入/无摘要降级）、
`AgentOrchestratorContextBudgetTest`（200 条消息请求不超窗）。前端 `ChatView` tokenPct 用例同步更新。

#### R-02 模型 fallback 链

**问题（证据）**：`CircuitBreakerLlmProvider` OPEN 时直接抛错；`LlmProviderRouter` 无备用模型概念。
本地 qwen2.5:7b 不可用时整个 agent 不可用。

**方案**：
1. `AgentConfig` 增加 `ai.llm.fallback-chains`：`default → qwen2.5:7b → deepseek-chat`（云端按已配置服务商）。
2. **实现层次**：fallback 在 `LlmProviderRouter` 层实现（`completeWithFallback()`），包裹完整的
   gate+breaker provider——熔断 OPEN 直接切换（不等待超时），仅超时/5xx/429 才消耗一次降级尝试。
   每次尝试有独立超时，整链延迟预算上限 60s。
3. 降级时发 `model_fallback` 事件（SSE/WS），前端模型徽章显示实际生效模型。
4. fallback 结果不写语义缓存（避免跨模型污染）；**不写用户模型偏好**（fallback 是请求级临时行为）；
   trace 记录 fallback 链、触发原因与耗时。降级次数按日限流并告警（防云端成本失控）。

**涉及模块**：`ai/llm/LlmProviderRouter`、`ai/llm/circuit/*`、`ai/agent/AgentOrchestrator`、
`service/ModelService`、`frontend/src/stores/websocket.js`。

**风险**：云端成本突增（加每日降级次数限制与告警）。

**验收**：停掉 Ollama 后聊天自动走云端并可感知；新增熔断→降级→恢复测试。

#### R-03 网页正文抓取工具（WebFetchTool）

**问题（证据）**：内置工具仅 `WebSearchTool`（无浏览器/抓取），调研与 RAG 扩展受限。

**方案**：
1. 新增 `WebFetchTool`：域名白名单（可配置）+ HTTP GET（HttpClient5，超时 10s，UA 标识）+ HTML 正文提取
   （jsoup，去 script/style/nav）+ 正文截断（默认 8000 字符）+ **响应体大小上限 1MB** + 统一"不可信数据"前缀。
2. **SSRF 防护（含重定向）**：URL 格式校验、协议仅 http/https；解析后校验目标 IP 非私网/环回/链路本地/保留段；
   **每个重定向 hop 重新解析并重复校验**（防 DNS rebinding）；跳转上限 5 次。
3. 前端工具列表自动可见（`/api/tools` 已动态）。

**涉及模块**：`ai/tool/builtin/web/WebFetchTool`、`config/AgentConfig`（白名单配置）、`pom.xml`（jsoup）。

**风险**：SSRF / 隐私（白名单 + IP 校验 + 结果截断）。

**验收**：白名单页面抓取正文成功、非白名单拒绝、内网地址拒绝、**重定向到内网拒绝**、注入攻击测试通过；
测试：`WebFetchToolTest`（正常/白名单/截断）、`WebFetchToolSecurityTest`（SSRF/重定向/DNS 解析注入）。

#### R-04 记忆纠错闭环

**问题（证据）**：记忆由蒸馏自动写入；`MemoryView` 仅搜索/导出，聊天内无纠错指令入口。

**方案**：
1. 聊天内纠错识别：在 `AgentOrchestrator` 工具轮前识别"删掉/修改/忘了 X"指令 → 直接调用记忆删除/更新
   （`MemoryRepository` 已有 delete/upsert），并回执"已修正记忆"。
2. 纠错动作写 trace span；记录到操作日志。
3. 删除采用"软删除/失效"而非物理删除：记忆记录标记 `invalidated=true`（含失效原因与时间），
   检索层过滤失效记录，MemoryView 提供恢复入口——避免误删不可逆。
4. `MemoryView` 增加行内编辑/置顶/失效/恢复按钮（复用 `MemoryProxyController` CRUD）。

**涉及模块**：`ai/agent/AgentOrchestrator`（指令识别）、`frontend/src/views/MemoryView.vue`、
`frontend/src/components/memory/MemoryCard.vue`。

**风险**：误删用户想保留的记忆（二次确认 + 软删除可恢复）。

**验收**：纠正后下一轮检索不再召回旧事实；软删除可恢复；前端 2 用例 + 后端 2 用例。

#### R-05 RAG 引用溯源

**问题（证据）**：`KnowledgeService` 分块入库（chunk 800/overlap 100，metadata 含 fileId/chunkIndex），
但召回内容不带来源，回答无引用，难以验证。

**方案**：
1. 检索结果保留来源元数据：`MemoryRecord` 已含 metadata；召回组装时生成 `[SOURCE: 文件名#段落N]` 标注注入上下文。
2. 回答事件流新增 `citation` 事件（SSE/WS），前端在回答底部渲染引用列表（可点击跳转知识库文件）。
3. 知识问答 prompt 增加"基于引用作答，不确定就说明"约束。

**涉及模块**：`ai/memory/ConversationMemoryService`（召回组装）、`ai/agent/AgentOrchestrator`、
`ai/llm/ModelEvent`、`frontend/src/components/chat/ChatMessageRow.vue`。

**风险**：引用噪声（只对 knowledge 类型召回加引用）。

**验收**：知识问答返回带来源引用；E2E 校验引用存在且指向正确文件。

#### R-06 评估套件扩充 + 门禁

**问题（证据）**：`golden-cases.json` 仅 8 例；`EvalSuite` 走真实 Ollama，`-Deval.min-score` 默认 2；
CI 无门禁 job。

**方案**：
1. 扩充到 30+：工具组合（搜索→计算→总结）、多轮对话、注入攻击（tool_result 含指令）、
   长会话压缩质量（上下文预算后的信息保持）、记忆纠错、引用溯源。
2. EvalSuite 支持云端模型 baseline（`-Deval.model`），输出 JSONL 对比报告。
3. CI 增加手动 `eval` job（已有 `workflow_dispatch` 先例），`min-score` 可配。

**涉及模块**：`backend/web/src/test/eval/EvalSuite.java`、`src/test/resources/eval/golden-cases.json`、
`.github/workflows/ci.yml`。

**风险**：LLM 评测抖动（固定 temperature=0 + 3 次采样取中位数）。

**验收**：新用例可跑通；CI 手动 job 可复用门禁；输出 JSONL 报告。

### P1 — 中期

#### R-07 子代理/多代理编排

**问题**：`AgentOrchestrator` 单 agent 串行 ReAct；复杂任务（调研+实现）无法并行。

**方案**：
1. `TaskPlanner` 产物（PlanStep 列表）中可并行的步骤 → `SubAgentExecutor`（Java 线程池，每子任务独立
   `AgentRequestContext`，共享记忆仓库），结果按序合并回主对话。
2. 子代理限定：只读研究类子代理默认开；带副作用工具默认禁。
3. trace 增加 `sub_agent` span（parent→child）。

**涉及模块**：`ai/agent/planning/*`、新增 `ai/agent/subagent/SubAgentExecutor`、`infrastructure/observability/*`。

**风险**：并发写记忆冲突（子代理只读 + 主线程统一写）。

**验收**：复杂任务拆 ≥2 子任务并行且结果正确合并；并发测试通过。

#### R-08 代码/工作区工具（方向待确认）

**问题**：`FileTool` 只读白名单、`ShellTool` 命令白名单；agent 无法编辑文件。

**方案（若确认定位编码 agent）**：
1. 新增 `FileEditTool`：白名单工作目录 + 正则路径校验（防 `..`）+ diff 预览 + `approvalRequired=true` 走 HITL。
2. 文件类型限制（文本类）；大文件拒绝；操作原子化（临时文件 + rename）。
3. 若保持个人助理定位：本条关闭，仅保留只读工具。

**涉及模块**：`ai/tool/builtin/file/FileEditTool`、`config/AgentConfig`、`ai/agent/approval/*`。

**风险**：误改用户文件（审批 + 备份 + 类型白名单）。

**验收**：白名单目录内编辑成功、目录外拒绝、审批流可用、`..` 绕过测试通过。

#### R-09 IM 渠道 HITL 审批

**问题**：`ApprovalGate` 审批卡片仅 web/WS；IM 渠道（飞书等）直发无审批。

**方案**：飞书卡片按钮（`FeishuCardBuilder` 已支持交互回调）承载审批事件；或 IM 渠道对
`approvalRequired` 工具默认拒绝并提示在 web 端批准。

**涉及模块**：`ai/agent/approval/*`、`integration/feishu/*`、`feishu/FeishuEventController`。

**风险**：卡片回调安全（签名校验已有）。

**验收**：飞书渠道发起审批并可卡片批准/拒绝；无按钮渠道默认拒绝。

#### R-10 成本/用量指标

**问题**：trace span 有耗时无 token/cost；无法按用户/模型看用量。

**方案**：
1. LLM span 记录 prompt/completion tokens（Ollama/OpenAI 响应均含）。
2. `AnalyticsService` 聚合每用户/模型 token 与估算成本（按模型单价配置表）；月限额超限拒绝新请求。
3. `StatsView` 增加成本卡片与用量趋势。

**涉及模块**：`ai/llm/LlmResponse`、`infrastructure/observability/TraceService`、
`domain/analytics/AnalyticsService`、`frontend/src/views/StatsView.vue`。

**验收**：管理端可查每用户/模型成本；限额生效测试。

#### R-11 加密密钥解耦

**问题**：`SecretCrypto` 密钥由 `JWT_SECRET` SHA-256 派生；轮换 JWT_SECRET 全部加密存量失效（已知债）。

**方案**：独立密钥文件（`data/keys/master.key`，权限收紧）+ keyId 版本化密文头（`v1:<iv>:<cipher>`），
支持多版本密钥并存；轮换时新写用新 key，旧密文按版本头用旧 key 解密。

**涉及模块**：`infrastructure/security/SecretCrypto`、`service/CloudService`、`integration/feishu/FeishuChannelClient`。

**风险**：密钥文件丢失（备份提示 + 启动自检）。
